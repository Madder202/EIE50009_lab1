## 2. 必须实现的功能（明确要求）

### 2.1 交互与公共规则（原文第 2 节）

- 逐行 REPL，提示符 `svg>`；支持以 `#` 开头的注释及双引号包裹的带空格参数。
- SVG 坐标系：左上角原点，向右为 x 正方向，向下为 y 正方向，浮点合法。
- 图形及 g 均有全局唯一、大小写敏感的 ID；create/group 必须显式提供 ID。
- read 对缺 ID 元素按标签名加序号自动分配，打印 `warning: assigned id rect1 to unnamed <rect>` 形式警告。
- 错误以 `error:` 开头，一行一条；失败不得改变任何状态。编辑成功打印摘要，显示命令直接打印内容。

### 2.2 命令全集（原文第 3—5 节）

| 命令 | 必须达到的行为 |
|---|---|
| init [w] [h] | 新建并替换当前画布，默认 800×600 |
| read <file.svg> | 读入 SVG 为当前文档，自动补 ID 并警告 |
| save [file.svg] | 保存 SVG；无参数保存到读入时路径 |
| canvas [w] [h] | 无参数查询尺寸，有参数修改尺寸 |
| create <type> <id> ... [in <containerId>] | 支持六种类型；省略 in 放在根下，提供 in 时目标必须存在且为 g；g 也支持 in |
| delete <id> | 删除目标，容器连同全部子孙删除 |
| move <id> <dx> <dy> | 按增量平移；容器整体移动 |
| scale <id> <factor> | 正数等比缩放，位置和尺寸均乘因子，容器递归作用于子孙 |
| set <id> <attr> <value> | 修改公共样式或该类型允许的几何属性；text 支持修改文本内容 |
| group <newGid> <id1> <id2>… | 新建 g，从原父容器收编目标，保持相对顺序；禁止同时选择祖先与其后代 |
| ungroup <gid> | 子图形提升到父级并占据原 g 的位置；禁止解散 svg 的直接子容器 |
| addto <gid> <id> | 移入已有容器，作为最后一个子节点 |
| front / back <id> | 在同级调整视觉前后顺序 |
| tree [id] | 全树或指定子树；内联关键几何属性，不能只打印 ID |
| show <id> | 显示类型、ID、父级及属性明细 |
| help | 显示全部命令和语法 |
| undo / redo | 撤销/重做编辑，每条编辑命令是一个单元；撤销后新编辑清空 redo |

### 2.3 类型和属性（原文第 4.1 节）

| 类型 | create 参数（ID 之后） | set 几何/内容属性 |
|---|---|---|
| rect | x y w h [fill] | x、y、width、height |
| circle | cx cy r [fill] | cx、cy、r |
| ellipse | cx cy rx ry [fill] | cx、cy、rx、ry |
| line | x1 y1 x2 y2 [stroke] | x1、y1、x2、y2 |
| text | x y "content" | x、y、text |
| g | 无 | 无几何或内容属性 |

公共 set 属性为 fill、stroke、stroke-width；其他属性报 `error: unknown attribute: <attr>`，包括通过 set 修改 id、transform、font-size 等。fill/stroke 省略时不序列化该属性，遵循 SVG 默认值，不能人为补成可见线条。

### 2.4 历史规则（原文第 4.3 节）

- create、delete、move、scale、set、group、ungroup、addto、front、back 可撤销重做；复杂结构编辑整体只占一个单元。
- tree/show/help 不进入历史栈。
- init/read/save 及 canvas 修改尺寸后禁止 undo 和 redo，报 `error: undo not allowed after io command`，直到下一条编辑命令重新解禁。
- canvas 无参数只是查询，不属于上述修改尺寸操作。
- 失败不改变任何状态，因此也不能清空 redo、修改当前路径或改变历史禁用状态。

### 2.5 固定错误文本（原文第 4.2 节）

| 场景 | 文本模板 |
|---|---|
| 重复 ID | error: id already exists: <id> |
| 图形不存在 | error: no such shape: <id> |
| in 容器不存在 | error: no such container: <id> |
| in 目标不是容器 | error: not a container: <id> |
| 未知类型（包括 box） | error: unknown shape type: <type> (is the plugin loaded?) |
| 分组包含祖先和后代 | error: cannot group a container into its own descendant: <ancestorId> |
| 解散根级容器 | error: cannot ungroup top-level container: <id> |
| 非正缩放 | error: scale factor must be positive |
| 读/写失败 | error: cannot read file: <path> / error: cannot write file: <path> |
| 无当前文档 | error: no document. use 'init' or 'read' first |

原文的 `cannot ungroup composite shape` 对应后续复合图形，本阶段不为该错误引入 box 或插件。

## 3. 架构和提交约束（明确要求）

1. TypeScript + 面向对象：类层次、多态、字段封装、一类一文件，文件名等于类名。禁止公共数据袋配合过程式函数和散落的 switch(tag)。
2. 必须使用 Command 模式；容器和叶子的 move/scale/set/delete 等操作遵守 Composite 语义。
3. 按名字分派只能位于命令分发及图形工厂两处，并在架构方案中标注待重构。SVG 导入等路径不能另建一套类型分派。
4. 原文允许架构层的未模块化，但不豁免 OO 范式；这是容许范围，不是要求采用上帝类或混合 IO。具体分层方案下一轮讨论。
5. 使用 AI 协作，真实记录关键讨论、发现的问题、确认及修正过程。
6. 全程 Git 分步提交并推送 GitHub/Gitee 等远程仓库，禁止最后一次性大提交；最终提交打 final 标签，须在截止前完成。建议同时推送标签，确保远程可核验。
7. 最终 `doc/README.md` 包含：模块职责及 PlantUML 组件/包图、模式选择与落地、依赖方向及理由、变化点及预留/不预留的理由、过程记录、一致性自查、质量保证手段。
8. 一致性自查必须对照实际目录和依赖，记录偏差与修订；质量保证需提供实际验证依据。

## 4. 未明确语义及建议决策

以下保留最初提案及问题背景，现已由用户统一确认，不能当作作业原文要求；README.md 记录生效规则。

| 编号 | 缺口或冲突 | 建议解释及验收影响 |
|---|---|---|
| D01 | group 未规定新 g 的父级/位置；跨父级的相对顺序无唯一定义 | 同父级时在最早被选位置插入；跨父级时放到所有目标的最近公共祖先容器，在最早相关分支前插入；内部按操作前文档深度优先顺序排列，而非参数顺序。跨父级可能改变与未选节点的遮挡关系，需明确接受该结果。重复参数拒绝；至少两个目标。最少数量也是建议，原文未严格定义。 |
| D02 | 文档操作后只写了禁止历史，未说明旧历史是否保留 | 成功 init/read/save/canvas 修改均清空两栈并设历史屏障；下一次成功编辑解除屏障，新历史不能越过它。失败命令及查询不解除。避免 read 后恢复到旧文档。 |
| D03 | 外部 SVG 的支持范围；背景给出了 transform 和非白名单文字属性 | 待核实：不能承诺读取任意 SVG。建议首阶段保证六种元素、嵌套结构及支持属性的往返；对于无法正确处理的 transform、单位、非标准 viewBox、未知元素/属性明确拒绝，避免静默丢失。此范围会拒绝部分背景示例，须在实现前确认是否需增加 transform、font-size、text-anchor 等导入支持；set 白名单不自动等于导入白名单。 |
| D04 | 普通 g 的 set 样式传播规则未写明 | 建议只设置 g 自身属性，使用 SVG 样式继承；不覆盖子孙显式样式。g 的 x/y/text 等不在白名单，仍报错。统一操作不代表每种类型支持相同属性。 |
| D05 | 无文档错误与启动提示 type help 存在张力 | 建议 help 在无文档时也可用；init/read 可建立文档，其余命令要求已有文档。help 例外偏离错误表字面表述，需明确记录。 |
| D06 | save 无参数在 init 后如何处理；另存路径是否成为默认路径 | 建议无读入路径时报错要求显式路径；严格按原文保持默认路径为最近成功 read 的路径，save 新路径不替换它。若希望保存后自动绑定新路径，需另作明确决策。init 清除读入路径。 |
| D07 | front/back “最前/最后”可能混淆数组顺序与视觉顺序 | 建议 front 为视觉最上层，即 SVG 同级最后一个节点；back 为视觉最下层，即第一个节点。 |
| D08 | 缺 ID 生成可能与后面已有 ID 冲突；重复 ID 外部文件如何处理 | 建议先扫描全部显式 ID，重复则整次 read 失败；再按文档顺序为缺失 ID 分配从 1 开始的最小可用标签序号。分配完成并读入成功后再打印警告。svg 根不视为可寻址图形。 |
| D09 | init/canvas 只给一个尺寸、负尺寸、NaN/Infinity 等未定义 | 建议 init 允许 0/1/2 个参数，单参数为宽度、高默认 600；canvas 允许 0 或 2 个参数。所有数值有限，画布宽高大于 0，几何尺寸和 stroke-width 非负，位置可负。算术溢出应原子失败。 |
| D10 | 引号转义、空行、行内注释和带空格路径未定义 | 建议支持空行、前导空白后的整行注释、双引号路径和空文本；不支持行内注释，保留颜色 # 值。引号内支持转义引号和反斜杠，普通 Windows 路径反斜杠保留；未闭合引号报错。 |
| D11 | addto 自包含、移入后代、重复移动及无效果编辑 | 建议禁止自包含和祖先移入后代；同父级 addto 移到末尾；成功的无效果编辑仍算一个历史单元并清空 redo，失败不算。 |
| D12 | scale 是否缩放描边宽度、字号；move g 的内部表示 | 明确要求仅几何位置/尺寸缩放；建议不缩放 stroke-width，不引入字号设置。容器 move 递归修改叶子坐标，scale 以全局原点为基准递归修改；不额外叠加 transform，避免双重变换。与 D03 导入策略一起确定。 |
| D13 | 空历史、未知命令、参数错误、多错误优先级、输出对齐未规定 | 建议定义统一错误目录；先解析语法，再检查文档/目标，再验证操作。固定错误逐字符合原文；成功摘要和 tree 缩进风格一致，但不要求任意列宽完全匹配。空历史分别报 nothing to undo/redo，屏障错误优先于空栈。 |
| D14 | SVG 根属性、显示数字、文件元素计数 | 建议输出标准 namespace、width/height 及匹配画布的 viewBox；计数包含 g 和叶子，不含 svg，与示例一致；规范化 -0，采用可往返的数值文本，测试浮点容差。XML 文本与属性正确转义，中文原样保留。 |
| D15 | REPL 退出与脚本回放机制未规定 | 建议 EOF 正常退出，支持标准输入回放；遵照示例提供 npm run cli。暂不扩展 exit 命令。 |

建议从“不改变任何状态”推导验收范围包括文档、ID 索引、父子关系、节点顺序、历史栈、历史屏障及默认路径。原文未规定文件写入中途失败的磁盘恢复策略，后续 IO 设计时应考虑临时文件替换。
